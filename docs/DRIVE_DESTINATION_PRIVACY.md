# Company recording destination privacy: initial policy

The future company upload path must call `validateRecordingDestinationImmediatelyBeforeFileCreation` using the authenticated host user ID and meeting/session identifiers immediately before creating any Drive file. Only a `SAFE` response may be considered for creation. The response is a point-in-time assessment, not a guarantee against subsequent permission, membership, credential, or destination changes. This phase creates no Drive file or upload session.

This intentionally restrictive first policy accepts only My Drive folders owned by the connected company account. The central Recording Sessions folder must be a direct child of that account's My Drive root. The selected batch folder, if any, must be a direct child of Recording Sessions and authorized for the host. The account root is inspected as an ancestor and is never the upload destination. If no batch folder is selected, the configured Recording Sessions folder itself is the destination.

The complete paginated permissions of every folder on that supported path must identify the verified company account as the only owner and only individual principal. Any other user, group, domain or anyone permission is blocked, including inherited permissions encountered on an ancestor. Published or malformed permissions, missing pages, scope restrictions, inaccessible ancestors, missing ownership/capability/version data, changed credentials or changing folder metadata are unverifiable. Shared drives are unverifiable because this policy does not establish their complete membership and inheritance. No assumption is made that a user with a company-looking email is approved. No additional administrators are configured by the application for this policy.

The current `drive.file` scope may not provide the required metadata, ancestor visibility or ability to inspect permissions for a real company account. Google does not provide an atomic snapshot spanning all these requests, and this validator cannot prevent changes immediately after the check. Do not enable company uploads or claim this policy protects against later Drive administrator changes. Real Google behavior and the chosen organization's Drive controls require separately authorized verification before any production use. Existing folder browsing and manually initiated uploads are not changed.
